# HelpDesk - система технической поддержки сотрудников

Курсовой проект по теме: "Разработка приложения для организации технической поддержки сотрудников".

Проект представляет собой сайт, где сотрудники компании могут создавать тикеты по техническим проблемам, отслеживать выполнение заявки и переписываться с техническим специалистом. Технический специалист видит общую доску обращений, меняет статусы, задает сложность, добавляет этапы выполнения и удаляет закрытые тикеты.

# Курсовой проект можно просмотреть на сайте - https://mptn.space/

## Стек

- HTML - структура страниц.
- CSS - минималистичный интерфейс, адаптация под мобильные экраны, цвета статусов.
- JavaScript - логика интерфейса, работа с тикетами, чат, запросы к API.
- Python - серверная часть.
- PostgreSQL - база данных пользователей, тикетов, этапов и сообщений.
- pg8000 - подключение Python к PostgreSQL.

## Основные возможности

- Регистрация сотрудников.
- Вход сотрудников по логину и паролю.
- Вход технического специалиста через общую форму авторизации.
- Создание тикетов по категориям.
- Просмотр всех тикетов, чтобы сотрудники не создавали повторяющиеся обращения.
- Вывод собственных тикетов сотрудника в верхней части боковой панели.
- HelpDesk-доска с распределением тикетов по статусам.
- Цветовая индикация тикетов в зависимости от статуса.
- Теги сложности для технического специалиста.
- Открытие подробной страницы тикета.
- Линия выполнения с этапами работы по тикету.
- Чат внутри тикета между сотрудником и техническим специалистом.
- Запрет сотруднику смотреть чат чужого тикета.
- Изменение статуса и сложности тикета техническим специалистом.
- Закрытие тикетов.
- Удаление закрытых тикетов техническим специалистом.
- Запоминание авторизованного пользователя в браузере.
- Адаптация интерфейса под мобильные экраны.

## Как зайти в админку

Отдельной кнопки "Техподдержка" нет. Вход технического специалиста выполняется через обычную форму входа.

Данные для входа:

```text
Логин: admin
Пароль: admin
```

После ввода `admin / admin` откроется панель технической поддержки.

## Тестовые пользователи

При первом запуске сервер автоматически создает тестовые данные, если база пустая.

Сотрудники:

```text
ivanov / 123
petrova / 123
```

Технический специалист:

```text
admin / admin
```

## Значение элементов интерфейса

### Страница входа

- Вкладка "Вход сотрудника" - вход для сотрудников и технического специалиста.
- Вкладка "Регистрация" - создание новой учетной записи сотрудника.
- Поле "Логин" - логин пользователя.
- Поле "Пароль" - пароль пользователя.
- Кнопка "Войти" - отправляет данные на сервер и открывает рабочую область.

### Левая панель

- Блок пользователя - показывает имя и роль текущего пользователя.
- Кнопка с крестиком - выход из аккаунта.
- Поиск по тикетам - фильтрует обращения по теме, категории, сотруднику и описанию.
- Кнопка "Показать по категориям" - открывает список тикетов, сгруппированный по категориям.
- "Мои тикеты" - обращения, созданные текущим сотрудником.
- "Все тикеты сотрудников" - остальные обращения, которые сотрудник может просмотреть без доступа к чужому чату.

### Главная рабочая область

- Кнопка "Создать тикет" - открывает форму создания новой заявки. Доступна только сотруднику.
- Кнопка "На главную" - возвращает с открытого тикета на доску.
- Статистика по статусам - показывает количество тикетов в каждом состоянии.
- HelpDesk-доска - отображает тикеты в колонках по статусам.

### Статусы тикетов

- "Новая заявка" - сотрудник только что создал обращение.
- "В работе" - технический специалист занимается проблемой.
- "Ожидает сотрудника" - специалисту нужна информация или проверка от сотрудника.
- "Выполнено" - проблема решена, но тикет еще не закрыт окончательно.
- "Закрыто" - обращение завершено.

Цвет карточки соответствует текущему статусу тикета.

### Сложность

Сложность используется техническим специалистом для внутренней оценки обращения:

- "Низкая" - простая задача.
- "Средняя" - обычная задача.
- "Высокая" - важная или сложная проблема.

### Страница тикета

- Категория - вид проблемы: оборудование, ПО, сеть, доступы или консультация.
- Название тикета - краткая тема обращения.
- Описание - подробности проблемы от сотрудника.
- Метаданные - сотрудник, отдел, дата создания и количество сообщений.
- Линия выполнения - история действий по тикету.
- Чат - переписка сотрудника и технической поддержки.

### Панель технического специалиста

Технический специалист может:

- менять статус тикета;
- менять сложность;
- добавлять новый этап выполнения;
- закрывать тикет;
- удалять тикет, если он уже закрыт.

## Категории тикетов

- Оборудование.
- Программное обеспечение.
- Сеть и интернет.
- Доступы и безопасность.
- Консультация.

## Запуск локально

### 1. Создать базу PostgreSQL

```sql
create database helpdesk_db;
```

### 2. Установить зависимости

Команду нужно выполнять из папки проекта:

```bash
pip install -r requirements.txt
```

или на Windows:

```powershell
py -m pip install -r requirements.txt
```

### 3. Запустить сервер

```bash
python server.py
```

или на Windows:

```powershell
py server.py
```

### 4. Открыть сайт

```text
http://localhost:8000
```

Открывать `index.html` напрямую из папки не рекомендуется, потому что сайт работает через серверное API.

## Настройка подключения к PostgreSQL

По умолчанию сервер использует строку подключения:

```text
postgresql://postgres:postgres@localhost:5432/helpdesk_db
```

Если логин, пароль или имя базы отличаются, нужно задать переменную окружения `DATABASE_URL`.

Пример для PowerShell:

```powershell
$env:DATABASE_URL="postgresql://postgres:ваш_пароль@localhost:5432/helpdesk_db"
py server.py
```

Пример для Linux:

```bash
export DATABASE_URL="postgresql://postgres:ваш_пароль@localhost:5432/helpdesk_db"
python3 server.py
```

## API

- `POST /api/register` - регистрация сотрудника.
- `POST /api/login` - вход пользователя.
- `GET /api/tickets` - получение тикетов.
- `POST /api/tickets` - создание тикета.
- `PATCH /api/tickets/{id}` - изменение статуса или сложности.
- `POST /api/tickets/{id}/steps` - добавление этапа выполнения.
- `POST /api/tickets/{id}/messages` - отправка сообщения в чат.
- `DELETE /api/tickets/{id}` - удаление закрытого тикета техническим специалистом.

## Размещение на сервере

Проект можно разместить на VPS. Рабочий вариант:

- Ubuntu 24.04;
- PostgreSQL;
- Python 3;
- systemd для постоянного запуска `server.py`;
- Nginx как обратный прокси;
- домен, направленный A-записью на IP сервера.

При таком размещении Nginx принимает запросы на домен и передает их локальному Python-серверу на порт `8000`.
